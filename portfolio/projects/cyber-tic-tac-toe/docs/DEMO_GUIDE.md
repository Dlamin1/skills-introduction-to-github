# Cyber Tic-Tac-Toe — Demo Recording Guide

Use this guide to record a short, professional gameplay demonstration for the project README.

## Recommended Demo Length

**45–90 seconds** is ideal.

The goal is to show the interface, difficulty selection, gameplay, AI response and score/result without recording an entire match.

## Before Recording

1. Install Python 3.10 or newer.
2. Confirm Tkinter is available.
3. Open a terminal in `portfolio/projects/cyber-tic-tac-toe/`.
4. Start the GUI:

```bash
python src/cyber_tic_tac_toe_gui.py
```

5. Close unrelated applications and notifications.
6. Resize the game window so the complete interface is visible.

## Suggested Recording Sequence

### Scene 1 — Opening (5–10 seconds)

Show the complete application window.

Suggested narration:

> "Cyber Tic-Tac-Toe is a Python desktop game built with Tkinter. It uses a shared game engine with three AI difficulty levels."

### Scene 2 — Difficulty (5 seconds)

Open the **AI Difficulty** selector and briefly show Easy, Medium and Hard. Select Medium or Hard.

### Scene 3 — Gameplay (20–40 seconds)

Play several moves and allow the Cyber AI to respond. Show the interactive board, player/AI symbols, AI response, status messages and score tracking.

### Scene 4 — Result (5–10 seconds)

Let the game reach a win or draw. Show the result message and updated scoreboard.

### Scene 5 — Close (5 seconds)

Optionally show the project folder or GitHub repository structure and say:

> "The project includes the Python game engine, Tkinter interface, automated tests and documentation."

## Recording Tips

- Record at 1080p where possible.
- Keep the game window centred.
- Avoid personal files, browser tabs, passwords or private notifications.
- Use a clear microphone if narrating.
- Keep the demo focused on the software.

## Suggested File Name

```text
cyber-tic-tac-toe-demo.mp4
```

## Media Location

If the video is hosted externally, place the link in the README's **Demo** section. For repository-hosted media, use `docs/media/` and avoid committing very large video files directly to Git.
